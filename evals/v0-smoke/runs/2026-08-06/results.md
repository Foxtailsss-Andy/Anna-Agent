## 结论与优先级

**通过的 3 案（H2/J1/L1）说明地基是好的**：诚实拒答、计划纪律、多工具链条 + 产物落地
（L1 一页汇总 10 项数字全中）都真实可用，trace 结构干净（无 orphan、turns 受控）。

**失败的 5 案收敛为 3 个根因**，均为确定性缺陷（非采样随机）：

1. **`TOOL_ERROR_FATAL`（S1）— 最高优先级**：一次工具参数错误 = 整个 run 归零、用户拿到 null。
   长任务上这是灾难性的。修法：工具错误作为 tool result 回喂模型自纠，而非 raise 终结 run。
2. **补查动作缺失（G1/R1，L1 部分）**：合并提问只命中一个口径就收尾，且**稳定复现**（0/3）。
   J1 已证明分步计划能拿全数据 → 修复方向是"用户子问题未被满足 → 触发补查"。
   因是确定性缺陷，修好后 pass^k 应直接 0/3 → 3/3。
3. **零值 stub 被当真数据（H1/G2）+ 日期不接地（G2）**：
   demo-erp 对越界期间返回 0 而非报错，Anna 全盘接收甚至据此推出经营结论；
   且模型自行推出 2025-11（system prompt 未注入当前日期）。
   修法：注入当前日期；诚实规则增加"0/空 + 期间越界 → 按无数据处理并明说"。

**红线**：FABRICATION **0 例**。所有可疑数字都溯源到工具真实返回——
Anna 没有杜撰过数字，问题在于**不加质疑地转述**上游的 0，以及**答不全就收尾**。
