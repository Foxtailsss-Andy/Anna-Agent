# 明远 Demo ERP — 中小企业经营/财务业务系统 设计文档集

> 版本 v0.1 · 2026-06-16 · 系统架构师交付,供 Roommate 照此开发
>
> 目标:一套**迷你但完整、数据自洽、有真实业务逻辑**的中小企业后台业务系统,作为 Anna
> 的真实数据源。参考 SAP S/4HANA(FI 财务会计 / SD 销售 / MM 采购 / CO 成本)与 Salesforce
> (CRM 客户/商机/应收)的模块划分,但裁剪到中小企业够用、可在 1–2 周内开发完成的规模。
>
> **核心原则**:Anna 只连 MCP,不感知底层系统。本系统通过一个 MCP 适配层把数据按固定契约
> 吐给 Anna。**现在建演示版,后期可平滑替换为更完整的真实版,Anna 零改动。**

## 1. 系统定位与边界

```
                          ┌──────────────────────────────────────────────┐
                          │            明远 Demo ERP (本系统)              │
   ┌─────────┐  MCP/RPC   │  ┌───────┐ ┌───────┐ ┌───────┐ ┌───────────┐ │
   │  Anna   │◀──────────▶│  │  FI   │ │  SD   │ │  MM   │ │  CO / EX  │ │
   │ (client)│  固定契约   │  │ 财务  │ │ 销售  │ │ 采购  │ │ 成本/费用 │ │
   └─────────┘            │  └───┬───┘ └───┬───┘ └───┬───┘ └─────┬─────┘ │
        ▲                 │      └─────────┴────┬────┴───────────┘       │
        │ 展示/对话         │              ┌──────▼──────┐                  │
   ┌────┴────┐            │              │  统一数据库   │  (主数据+交易+总账)│
   │  用户    │            │              └─────────────┘                  │
   └─────────┘            └──────────────────────────────────────────────┘
```

- **本系统**:中小企业的「经营 + 财务」后台。它**自己能跑**(有主数据、交易单据、总账、能出财报),
  不是给 Anna 凭空捏数字的桩。
- **MCP 适配层**:本系统对外开放的一层薄接口,把系统数据翻译成 Anna 要的 5 个 ERP 工具
  (见文档 04)。Anna 通过它读经营/财务数据、写催收任务。
- **不在本系统范围**:差旅报销的**单据创建/审批/发票OCR**由室友的**报销系统**(独立云端 MCP)负责;
  本系统只提供报销要用的**主数据**(部门/成本中心/员工/项目)并接收报销产生的**费用入账**(GL)。

## 2. 模块地图(对标 S/4HANA + Salesforce,裁剪到中小企业)

| 模块 | 对标 | 职责 | 支撑 Anna 的 |
|---|---|---|---|
| **ORG 组织主数据** | S/4 Enterprise Structure | 公司、部门、成本中心、员工、项目、会计科目表 | 报销维度、费用归集、CO 分摊 |
| **CRM 客户 + SD 销售(O2C)** | Salesforce + S/4 SD | 客户、商机(可选)、销售订单 → 销售发票 → 应收 → 收款 → 账龄 | 财务助手(应收)、Associate(催收)、看板(收入/AR) |
| **MM 采购(P2P)** | S/4 MM | 供应商、采购订单 → 供应商账单 → 应付 → 付款 → 账龄 | 财务助手(应付)、看板(费用/AP) |
| **FI 财务会计(总账)** | S/4 FI-GL | 复式记账、凭证、试算平衡、P&L/资产负债/现金流、期末结账、期间汇总 | 看板全部指标、数据一致性的根 |
| **CO 成本/管理会计** | S/4 CO | 成本中心归集、费用按类别/部门分摊 | 看板异常(市场费用跳增)、财务助手(费用明细) |
| **EX 费用与报销** | S/4 Travel & Expense | 员工费用单 → 入账;主数据供室友报销系统 | 报销主数据对齐、费用 GL |
| **AR Collections 应收催收** | S/4 FSCM / Salesforce | 逾期应收 → 催收任务(草稿/审批/执行/回读) | Associate 写入与回读 |
| **Analytics 经营分析** | S/4 Embedded Analytics | 从 FI/AR/AP 派生看板指标 + 异常识别 + 建议动作 | 财务经营看板 |

## 3. 分层架构与技术选型

```
┌──────────────────────────────────────────────┐
│  MCP Adapter Layer  (JSON-RPC 2.0 / HTTP)      │  ← Anna 只看这层(契约见文档04)
├──────────────────────────────────────────────┤
│  Service / Domain Layer                        │  ← 业务逻辑、记账、账龄、结账、催收状态机
│   (O2C / P2P / FI-GL / CO / Collections)       │
├──────────────────────────────────────────────┤
│  Repository / ORM Layer                        │  ← 数据访问
├──────────────────────────────────────────────┤
│  Database (关系库)                              │  ← 主数据 + 交易单据 + 总账(文档01)
└──────────────────────────────────────────────┘
```

**推荐技术栈**(中小团队、快速、可演示、易迁移):
- **DB**:演示用 **SQLite**(零运维);若与室友真实系统统一,选 **PostgreSQL**。Schema 一致(文档01)。
- **后端**:**Python FastAPI**(与 Anna 演示连接器同栈,集成最省事)或 **Node.js/NestJS**。
- **MCP 适配**:复用/扩展现有 `tools/demo_mcp_connector`(已实现 JSON-RPC 信封 + 工具路由),
  把数据来源从写死改成查本系统。
- **种子**:`seed.py`/`seed.sql`(文档03),一键灌一套自洽演示数据。
- **(可选)管理后台**:一个简单的 CRUD UI 看/改数据(让演示更可信),非必须。

> 选型理由:FastAPI + SQLite 半天能跑通;若直接上 Postgres + 完整后端,1–2 周可做成"真能用"的小 ERP。
> 两者 Schema 与 MCP 契约完全一致,先 SQLite 演示、后 Postgres 转真实,无缝。

## 5. 与 Anna 的对接(摘要,详见文档04)

Anna 需要的 5 个 ERP MCP 工具,各自由本系统哪个模块/查询支撑:

| Anna MCP 工具 | 支撑模块 | 数据来源 |
|---|---|---|
| `erp.finance.get_dashboard_snapshot` | Analytics ← FI/AR/AP/CO | 期间汇总 + 异常识别 + 建议动作 |
| `erp.finance.query` | Analytics ← FI/AR/AP/CO | 自然语言问答(关键词路由到应收/费用/收入/应付) |
| `erp.finance.get_receivables_aging` | AR ← SD | 未收销售发票按账龄分桶 |
| `erp.collection_task.create_draft` | AR Collections | 创建催收任务,返回 `external_task_id` |
| `erp.collection_task.get_status` | AR Collections | 回读催收任务状态 |

报销主数据(部门/成本中心/员工/项目)由 ORG 模块提供,供室友报销系统校验对齐。

## 6. 交付与验收(摘要,详见文档05)

- **P0(半天)**:Schema + 种子 + MCP 适配读库 → Anna 4 模块能跑通(看板/助手/Associate/报销主数据)。
- **P1(数天)**:补齐 O2C/P2P 单据流 + 复式记账,使财报由单据真实推导;加管理后台 CRUD。
- **验收**:用 Anna 的 ERP 探针(文档05提供)跑 9 条一致性/契约检查全过。
- **迁移**:真实系统就绪后,MCP 适配层把数据源切到真实库/真实 REST,契约不变,Anna 零改。
