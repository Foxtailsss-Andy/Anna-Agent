## 1. T04 outcome

T04 implements Skills, RunProfiles, Run Context and channel-scoped Memory for the
TypeScript Harness v2 control plane. A Run now receives one immutable, hashed
profile snapshot at the Run-start seam. Memory remains provenance-bearing and
human-controlled: a proposal is not Channel Memory until the Channel Owner
accepts it.

Delivered behavior:

- Agent Skills load from `SKILL.md` frontmatter with stable identity, version,
  content hash, provenance and explicit allowed/forbidden Tool declarations;
- RunProfile resolution intersects Channel, Worker, RunProfile and Skill Tool
  permissions, and rejects models, Skills, Memory modes or Artifact contracts
  outside their owning policy;
- the resolved snapshot includes Worker instructions, model policy, Skills,
  allowed Tools, budget, context transforms, Memory policy, Eval/Artifact policy
  and terminal rules;
- the snapshot is deep-frozen, content-addressed and strictly parsed on restore;
  unknown fields, tampered hashes and mismatched Worker/Profile identity fail
  closed;
- `claimRunWithResolvedProfile` resolves and validates the profile before one
  scoped Event Store claim, and SQLite close/reopen restores the exact snapshot;
- Run Context parsing binds every pending Tool call to Workspace, Channel, Run and
  Worker; compaction preserves goal, constraints, pending Tool calls, Memory hits
  and provenance;
- Channel Memory proposals require a source Run and source Event IDs that exist
  in the scoped Event Store;
- only an authorized Channel Owner can accept, reject, edit or delete a candidate
  or accepted Memory; deletion leaves an inspectable audit tombstone;
- Workspace Memory reads require an explicit source-Channel grant, retain grant
  provenance, and stop returning memories after revocation;
- retrieval can append provenance-only `memory.hit` events to a started Run;
- no automatic write from a failed Run or model output promotes data into Channel
  Memory.

## 2. Boundary preserved

T04 does not implement Trace/Eval projection, Scheduler, Crew behavior, desktop
cutover, legacy Python changes, Git push/merge/deploy or a production Sandbox.
T03 ToolGateway, Event Store, scope, Worker and Tool call ID requirements remain
mandatory. The `memory.hit` event is canonical evidence for the later T05 Trace
projection; T04 does not claim that projection is complete.

## 3. TDD evidence

Observed red states included:

1. Existing Run/StartRun fixtures used the former `{id, version, hash}` profile
   shape and were rejected by the strict snapshot parser;
2. the snapshot parser incorrectly treated every possible budget key as required,
   rejecting valid `{turns, toolCalls}` budgets;
3. the durable resolved-profile test did not construct branded IDs and failed the
   repository type boundary;
4. profile changes after Run claim could otherwise alter the restored configuration
   unless the resolved snapshot was persisted and cloned.

The accepted fixes use the public Run-start, Event Store and Run Context seams.
