## 4. Runtime behavior

Canonical event vocabulary introduced by T01:

```text
run.started
run.progress
run.tool.started
run.tool.completed
run.completed
run.timed_out
run.cancelled
run.failed
```

`message_start`, every Pi `message_update`, and `turn_end` produce ordered progress events. Message text/deltas, prompts, Tool arguments/results and provider error text are not copied into canonical events.

Each Run owns a monotonic sequence starting at zero. `EventSink.append` is awaited; append failures reject `start()` and cannot be converted into a successful or ordinary failed product outcome.

The single Pi Tool is a TypeBox-derived `fixture_read` adapter. It creates a channel-scoped `ToolRequest` and invokes the injected `ToolGateway`. T01 tests/canary use an in-memory Gateway; policy, approval, effect ledger and Sandbox remain T03 work.

## 5. TDD evidence

1. StartRun accepted a missing goal; the schema now requires a non-empty goal.
2. The adapter module did not exist; the first blocked stream test could not import it.
3. Wall/turn budget fixtures returned `completed`; they now stop before the next provider call and return `timed_out`.
4. Steer was absent from the next provider context; it now appears exactly once at the next valid turn boundary.

6. Pi received no Tool; it now receives exactly one `fixture_read` Tool and executes it through ToolGateway.
7. Provider error mapped to `completed`; Pi `stopReason="error"` now maps to `failed`.
8. A blocked provider could outlive wall time; a real timer now aborts it and returns `timed_out`.
9. A natural first-turn completion at `turns=1` was marked timed out; only a required next model call consumes the exhausted-turn gate.
10. Canonical usage included Pi-derived zero cost/total fields and could persist into a later missing-usage turn; usage is now turn-local and token-only.
11. Pi `message_update` produced no canonical evidence; each update now appends redacted progress before terminal completion.
12. The Tool schema used `as never`; it now uses TypeBox `Type.Object` / `Static`, and missing required arguments are rejected before Gateway execution.
13. EventSink failures were swallowed as Run outcomes; progress and terminal append failures now propagate to the caller.
