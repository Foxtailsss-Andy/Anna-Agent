## 1. T02 outcome

T02 is complete. Anna now has a canonical, channel-scoped Event Store with interchangeable InMemory and local SQLite implementations.

Delivered behavior:

- root `EventStore` exposes only `scope(ChannelScope)`; read/write operations exist only on a bound `ScopedChannelStore`;
- Channel scope is runtime-validated and snapshotted, so later mutation of the caller's object cannot switch the bound Channel;
- Channel+Stream event sequences start at zero and remain contiguous;
- an exact event retry is a no-op, while conflicting event IDs or sequence versions fail;
- one terminal event seals the stream against every later event;
- StartRun commands are idempotent by command ID and unique by Run ID;
- each Channel has one durable ChannelSession identity;
- projections are fenced and keyed by `(Channel scope, projector, stream)` with source-event receipts and persisted `lastSeq`;
- queued, running and all six explicit Run outcomes rebuild from command/event facts;
- restart reconciliation marks orphaned running Runs once as `run.failed { errorType: "process_restarted" }`;
- file-backed SQLite survives close/reopen and an actual child-process exit without `close()`.

T02 did not add Tool policy, approval, effect execution, Sandbox, Memory, Trace/Eval, Scheduler, Crew behavior, desktop cutover or T03 implementation.

## 2. Public contract

The portable Store contract lives in `packages/harness-v2`:

```text
EventStore.scope(ChannelScope) -> ScopedChannelStore

ScopedChannelStore:
  append(event)
  read(streamId, afterSeq?)
  claimStart(command)
  getCommand(commandId)
  getRunCommand(runId)
  claimChannelSession(session)
  getChannelSession()
  loadProjection(projector, streamId)
  commitProjection(commit)
  activeRunIds()
```

The root Store has no global `read` or `append` method. `ScopedChannelStore.append` remains compatible with the T01 `EventSink` seam.

## 3. Event and lifecycle rules

- `seq` is scoped by workspace, Channel and stream, starts at `0`, and equals the current stream version before append.
- Stream version is the next expected sequence number.
- Event IDs are unique within a Channel, including across different streams.
- Exact event retries do not advance the stream.
- After a terminal event, any new event is rejected; an exact retry of the existing terminal remains a no-op.
- StartRun claim persists the command without writing a queued event, preserving T01's `run.started seq=0` contract.
- A claimed command with no event reconstructs as queued; started/progress reconstruct as running; terminal events reconstruct the matching explicit RunOutcome.

## 4. Channel Session and restart behavior

`ChannelSessionService.open(store, session)` first claims the durable ChannelSession, then exposes the bound Run lifecycle. A second ID for the same Channel is rejected.

Reconciliation semantics are deliberately narrow:

- queued Runs stay queued;
- awaiting-input, awaiting-approval and terminal Runs remain unchanged;
- running Runs with no terminal receive one `run.failed` restart event;
- concurrent reconcilers both resolve, but optimistic sequence/terminal fencing permits only one restart terminal event;
- T02 does not resume the model or replay Tool effects.

Clock and event-ID creation are injectable for deterministic tests.

## 5. Projection rules

Projection identity includes both projector and source stream. A receipt contains the source stream, event ID and event sequence.

`projectNext`:

1. loads `(projector, stream)` state and `lastSeq`;
2. reads only later source events;
3. runs the reducer outside the SQLite transaction;
4. atomically commits state plus receipt with expected-version fencing;
5. leaves no state or receipt when the reducer fails.

An existing receipt prevents the reducer from being called again for an acknowledged source event.

## 6. SQLite implementation

Package: `packages/event-store`

SQLite uses built-in `node:sqlite` `DatabaseSync`; there is no native addon or fallback dependency. The API is isolated in `src/sqlite/migrations.ts` and the adapter.

Tables:

```text
schema_migrations
events
stream_heads
commands
channel_sessions
projections
projection_receipts
```

Runtime settings:

```text
journal_mode = WAL
synchronous = FULL
foreign_keys = ON
busy_timeout = 5000ms
```

Append, command/session claim and projection commit use short `BEGIN IMMEDIATE` transactions with commit/rollback. A database whose migration version is newer than the supported version fails closed with `UnsupportedSchemaVersionError` before v1 SQL is applied.

## 8. Crash/rebuild evidence

A controlled child process loads the public `SqliteEventStore`, commits a command plus running events, and exits with code `73` without calling `close()`. The parent process reopens the same file and verifies:

- the Run reconstructs as running;
- source events remain ordered and readable;
- projection state can be rebuilt solely from source events;
- no Pi JSONL/session file participates in recovery.
