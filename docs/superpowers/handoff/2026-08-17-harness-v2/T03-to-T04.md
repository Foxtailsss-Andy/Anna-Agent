## 2. Public contract

The portable contract remains in `packages/harness-v2`.

```text
createToolGateway({
  catalog,
  scope,
  workerProfileId,
  policy,
  sandbox,
  events,
  createEventId?,
  now?
}) -> DurableToolGateway

DurableToolGateway:
  execute(ToolRequest, AbortSignal) -> ToolResult
  answerApproval(ToolApprovalAnswer) -> void

ToolRequest:
  workspaceId / channelId / runId / workerProfileId
  name / input / toolCallId
  effectKey?     # required by effectful approved Tools
```

The factory snapshots `scope` and rejects a request whose Workspace, Channel or Worker differs. `ToolRequest.toolCallId` is mandatory. Direct test doubles may still implement the small `ToolGateway` interface, but the Pi integration suite also runs through the real bound factory.

## 3. Catalog, policy and lifecycle

The Gateway flow is:

```text
bound scope
→ tool.requested
→ catalog lookup
→ schema parse / normalized input
→ scoped policy decision
→ approval when required
→ effect ledger claim
→ Sandbox
→ tool.result
→ Pi observation
```

Dedicated Tool lifecycle streams use:

```text
tool:<runId>:<toolCallId>
```

Canonical lifecycle events are:

- `tool.requested`;
- `tool.policy.decided`;
- exactly one `tool.result` per Gateway attempt.

Lifecycle payloads contain scope correlation, Tool name, Tool call ID, optional effect key, status and a safe reason. They do not persist raw Tool input, file content, provider output or raw errors.

## 4. Durable approval

Approval facts are written to the Run stream:

- `tool.approval.requested`;
- `tool.approval.answered` with `approved | denied`.

Rules:

- no Sandbox execution occurs before an approval answer;
- a recreated Gateway reads the durable answer rather than process memory;
- the first matching answer is authoritative;
- a denied answer remains denied across recreation and does not open a new request;
- SQLite close/reopen conformance proves the request and answer survive restart.

Pi maps `approval_required` to a safe error observation, stops the automatic Tool batch and emits one terminal `run.awaiting_approval` event.

## 5. Effect ledger

Effect streams use:

```text
effect:<effectKey>
```

The first `tool.effect.started` records a SHA-256 intent hash over bound scope, Run, Worker, Tool, replay policy and normalized input. Reusing the same key with a different intent returns `effect_key_conflict` before Sandbox execution.

Terminal effect events are:

- `tool.effect.succeeded`;
- `tool.effect.failed`;
- `tool.effect.cancelled`;
- `tool.effect.unknown`.

Known success, failure and cancellation results are reused. Failure persistence retains only status and a safe string reason. An orphaned `started`, a thrown Sandbox call after dispatch, or an explicit unknown result becomes visible unknown and is never automatically replayed.

One in-process coordinator makes concurrent Gateway instances sharing the same Event seam await one execution. Event Store sequence fencing remains the durable cross-instance backstop. InMemory and SQLite property-style tests cover 1, 2, 5 and 20 repeated calls; the Sandbox executes once for each effect key.

## 6. Sandbox seam and local worktree Tools

`createDeterministicFakeSandbox` has a deterministic `wait_for_abort` script. It records the exact request and signal, exposes an execution-started promise, observes one abort and returns a safe cancelled Tool result. No wall clock is involved.

`createLocalPreviewWorktreeToolCatalog` exposes exactly:

```text
read_workspace  replayPolicy=safe
bounded_patch   replayPolicy=never
```

`read_workspace`:

- accepts one relative path;
- opens only a regular file;
- reads through a bounded file handle rather than loading the whole file;
- returns relative path, bounded UTF-8 content and `truncated`.

`bounded_patch`:

- accepts `{ path, expected, replacement }` only;
- requires one effect key and one exact occurrence of `expected`;
- limits input, source and result bytes;
- writes one same-directory exclusive temporary file, syncs it and atomically renames it;
- returns one changed path and before/after SHA-256 hashes;
- uses no-follow, post-open realpath/inode checks, parent revalidation and a final inode/content-hash CAS before rename.

Path traversal, absolute paths, directory symlink escape, file symlink escape and sibling writes fail without disclosing the host path or external file content.

## 7. Production Sandbox boundary

Production containment is explicitly **not implemented** in T03.

The deterministic fake proves the interface and cancellation contract. The local-preview worktree adapter adds path, symlink, descriptor and compare-and-swap checks, but it is still an in-process host adapter. Node path checks cannot close every hostile filesystem race or provide process, syscall, network, credential or host-home isolation.

Do not describe either adapter as host isolation. A real containment adapter remains required before production execution.

## 8. Pi mapping

Pi still exposes only Anna-owned Tools; built-in Bash/Write/Edit remain absent. The `fixture_read` canary now forwards Pi's real Tool call ID to ToolGateway.

The Pi integration tests run `fixture_read` through the real bound `createToolGateway` with typed schema, policy, canonical events and Sandbox. A Tool result maps to:

- succeeded: the existing safe output observation;
- failed/unknown: `details.status`, optional safe `reason`, and `isError=true`;
- approval required: `terminate=true` and Run outcome `awaiting_approval`.

`run.tool.started` and `run.tool.completed` include the same `toolCallId`. They do not include Tool arguments or raw results.

1. real Pi built-in `bash` reached no production Gateway implementation;
2. policy was not consulted and denied Tools had no scoped decision evidence;
3. approval request/answer did not exist and recreation lost the decision;
4. duplicate effect keys executed the Sandbox twice;

8. valid read and bounded patch Tools returned `tool_not_implemented`;
9. concurrent Gateway instances executed one effect eight times;
10. Tool lifecycle streams were absent for deny, unregistered, success and approval paths;
11. Pi dropped Tool call correlation and mapped unknown to a generic error;
12. approval-required Runs continued to `completed`;
13. scope/Worker spoofing was not rejected by a bound Gateway;
14. one effect key could be reused for a different Run intent;
15. invalid schema input had no terminal canonical result;
16. thrown unknown outcomes were durable only after a later retry;
17. bounded patch could overwrite a source changed before its final commit check.

Each accepted red was converted through the public Gateway, Store, Sandbox or Pi seam. An attempted watcher-based last-instruction filesystem race test was removed because it was nondeterministic without adding an unacceptable production sleep or test-only hook; the residual host-race limitation is documented in section 7.
