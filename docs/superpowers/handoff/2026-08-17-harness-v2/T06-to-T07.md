> Date: 2026-08-20

## 1. T06 outcome

T06 adds a durable local scheduler boundary on top of the scoped Event Store.
The implementation keeps schedule, occurrence, notification and trigger facts
in the same Workspace/Channel scope and keeps proactive Run metadata attached
to the persisted command and rebuilt Run.

Delivered behavior:

- explicit, unresolved-thread SLA, waiting-node deadline, connector-event and
  monitor trigger kinds have strict parsers;
- connector and monitor schedules require a durable trigger registration;
- fixed-interval recurrence uses a deterministic ManualClock and supports only
  explicit `tick()` and `recover()` execution;
- occurrence claim is atomic across InMemory and SQLite stores;
- `skip` persists a skipped occurrence so a later tick cannot execute it;
- `run_latest` claims one deterministic due occurrence and links the Run,
  trigger and audience to one notification;
- lifecycle append is atomic/idempotent, and owner-bound execution leases use
  Store time plus heartbeat renewal plus a durable `started` fence to prevent
  duplicate execution across SchedulerService instances; once an occurrence
  is fenced, a failed `createRun` is not automatically retried;
- local runtime status is exposed by `/api/admin/runtime/status` as
  `execution_mode=local`, `runs_while_app_closed=false` and
  `recovery_mode=explicit`;
- SQLite schema migration is now version 5 and rejects future versions.
