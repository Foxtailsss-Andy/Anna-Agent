# ADR-002:Agent 路线与代码路线的判定原则

> 日期:2026-06-12
> 状态:已决策
> 背景:Anna 是面向 2B 领域的 Agent Harness 系统。为防止两种常见走偏——"什么都让模型做"(慢、贵、不可控)和"什么都硬编码"(退化成普通 CRUD 系统)——固化本判定原则。所有新功能设计先过这张表。

## 一句话原则

**需要理解、判断、生成、规划的,走 Agent 路线(Skill + 模型 + 工具白名单 + Harness 治理);规则确定、可枚举、可校验的,走代码路线。** 模型负责"想",代码负责"管"。

## 判定表

| 任务特征 | 路线 | Anna 中的实例 |
|---|---|---|
| 理解自然语言意图、生成内容、跨数据综合分析 | **Agent** | Chat 回答、财务助手分析、Associate 目标拆解、Create 草稿生成 |
| 选择"调用哪个工具、带什么参数" | **Agent**(在白名单内) | 模型在 Skill 允许的 MCP 工具中选择 validate_draft/create_draft |
| 工具是否允许被调用 | **代码**(注册表 + assert_allowed) | ToolRegistry 白名单、backend-only 写工具不可见 |
| 数据校验、格式检查、必填字段 | **代码** | Skill required_fields 门、draft schema 校验、附件引用预检 |
| 审批、幂等、哈希证据、读回校验 | **代码**(永不交给模型) | approval 快照/哈希、submit 幂等键、readback 验证 |
| 审计记录 | **代码**(自动,模型无法跳过) | AuditService、严格递增时间戳 |
| 配置缺失/连接器不可用的处理 | **代码**(显式失败,不让模型编) | model_not_configured / connector_not_configured |
| 重试、退避、错误分类 | **代码**(传输层) | H1 模型传输加固 |
| 把模型输出转成系统状态 | **代码**(解析+校验后入库) | emit_goal_plan → GoalSpec、emit_skill_draft → SkillLoader 校验 |

## 推论(设计时直接引用)

1. **模型的每个输出都要过代码门**:生成 ≠ 生效。Create 草稿过 SkillLoader + 注册表校验,Associate 计划过 schema + 审批,报销提交过审批 + 幂等 + 读回。
2. **给模型的上下文里只放它需要"想"的信息 + 它被允许使用的能力清单**(Create 注入注册工具清单就是此推论的应用);不给它系统内部状态的修改权。
3. **不为"看起来智能"而把确定性逻辑塞给模型**:金额合规规则、税号校验位这类有标准算法的,写代码,模型只负责解释结果。
4. **不为"省事"把判断硬编码**:意图识别、字段抽取不许用 regex 冒充(项目史上的教训,见 2026-05-29 进度报告第 2 节)。
5. 拿不准时问两个问题:"这个决策错了谁负责?"——需要人审批的写操作永远走代码门;"这个逻辑明天会变吗?"——经常变的业务判断倾向 Skill(提示词)而非代码,稳定的规则倾向代码。
